# Сверка контекста агентов

Запускается из `home`. Цель — найти и исправить устаревшее в контексте, который читают агенты: `home/AGENTS.md`, `home/workflow.md`, `home/.agents/skills/`, `AGENTS.md` соседних репозиториев, `../documentation`.

## Шаги

1. **Свежесть.** `sh scripts/clone-repos.sh` — склонировать недостающее и подтянуть изменения.
2. **Репозитории.** `gh repo list tinkoff-trade-strategies-checking --json name,visibility,isArchived,defaultBranchRef` — сравнить с разделом «Репозитории» в `AGENTS.md` и списком в `scripts/clone-repos.sh`: новые, переименованные, закрытые, основная ветка.
3. **AGENTS.md репозиториев.** Для каждого `../<repo>/AGENTS.md`:
   - команды из раздела «Команды» существуют (скрипты в `package.json`, задачи Gradle, пресеты CMake) — не запускать тяжёлое, только проверить наличие;
   - пути из «Структуры» существуют;
   - ссылки на `home/...` и `../documentation/...` ведут на существующие файлы;
   - нет репозитория с кодом, но без `AGENTS.md`, — отметить.
4. **Ссылки на ID.** ФТ-N, НФТ-N, INV-N, UC-N, упомянутые в `AGENTS.md`, `workflow.md` и коде, существуют в `../documentation`.
5. **Документы против кода.** Выборочно: `../documentation/architecture.md` (модули, связи) против кода `backend` и `core`; ADR со статусом «предложен», которые код уже реализует или опроверг; вопросы в `status.md`, на которые код уже ответил.
6. **Слой проверки.** `python scripts/project-health.py` — у каждого репозитория с кодом есть «Команды», CI, обязательные проверки в ruleset, `CODEOWNERS`; на доске у задач есть Status, Size, Priority; открытые issue — на доске. Пробелы — по скиллу `next`, шаг 4.
7. **Скиллы.** Скиллы в `.agents/skills/` ссылаются на существующие инструменты и пути; у каждого скилла для Claude Code есть переходник в `.claude/skills/` и запрет переходника в `opencode.json`.

## Результат

- Очевидное и механическое (пути, ссылки, список репозиториев, команды) — исправить: по PR в каждом затронутом репозитории.
- Спорное (документ и код расходятся по смыслу, архитектурное решение под вопросом) — не решать молча: перечислить в ответе и предложить завести issue на доске.
- В конце — короткий список: что исправлено (с PR), что требует решения команды.
