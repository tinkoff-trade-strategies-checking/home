# Что дальше

Проект сам говорит, чего ему не хватает. Скилл превращает это в задачи на доске и выбирает, за что взяться. Запускается из `home`.

## Шаги

1. **Свежесть.** `sh scripts/clone-repos.sh` — без этого факты о локальных файлах устаревшие.
2. **Факты.** `python scripts/project-health.py` (или `--json`). Уровни: «Мешает работе», «Пробелы», «К сведению», и список задач Ready без исполнителя по приоритету.
3. **Мешает работе — первым делом.** Красный CI на основной ветке, нет доступа, нет клона — чинить сейчас или, если это чужая зона, оставить комментарий в issue или PR владельцу.
4. **Пробелы → задачи.** На каждый пробел без задачи:
   - поищи дубль: `gh search issues --owner tinkoff-trade-strategies-checking --state open "<ключевые слова>"` и задачи на доске — **дубль не заводи**, а дополни существующую комментарием;
   - мелкое механическое (поле на доске, issue не на доске, ссылка в AGENTS.md) — исправь сразу, без задачи;
   - остальное — issue в репозитории, где будет изменение (шаблон «Задача»), на доску со Status = Backlog, Size и Priority по `workflow.md`. Слой проверки репозитория с кодом — High; оценка ревьюера и чистка правил — Medium.
   - **Решение команды** (продукт, архитектура, спор в требованиях) — не решай сам: issue с меткой `question`.
5. **К сведению.** Старые PR — проверь, ждут ли ревью (`pr-review`) или автора; зависшие In progress — комментарий в issue с вопросом о состоянии. Ничего не закрывай и не переназначай без человека.
6. **Выбор задачи.** Из Ready без исполнителя: сначала Urgent, потом High, при равенстве — меньший Size и то, что разблокирует другие задачи (ссылки «блокирует» в issue, порядок контракта ADR-0007). Не бери то, что ждёт решения команды.
7. **Итог пользователю** — коротко: что мешает, какие задачи заведены или дополнены (ссылки), что исправлено сразу, и предложение: «беру `<repo>#<N>` — <почему>». Работу по выбранной задаче начинай по `workflow.md` — с `scripts/worktree.sh start`.

## Самосовершенствование

Если по ходу работы ты заметил, чего не хватает самому проекту — проверки, команды, правила, документа, скилла, — это тоже пробел: заведи задачу по шагу 4 или исправь сразу, если мелко. Если `project-health.py` чего-то не видит, а должен был, — допиши проверку в скрипт тем же PR, где заводишь задачу.
