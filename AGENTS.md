# home — точка входа для ИИ-агентов

Home-репозиторий проекта «Т-Инвестиции: тренажёр и лаборатория стратегий» (паттерн [Home Repo](https://www.aihero.dev/the-home-repo-pattern)). Агенты запускаются отсюда; код и документация лежат в соседних репозиториях, здесь — указатели на них, общие правила, скиллы и материалы, не принадлежащие одному репозиторию.

## Репозитории

Все лежат рядом с `home` в одной папке. Нет локально — склонируй: `scripts/clone-repos.sh` (или `git clone` из ссылки). Перед работой в репозитории: `git -C ../<repo> pull`, затем прочитай его `AGENTS.md`, если он есть.

- **documentation** (продуктовая документация: требования, инварианты, юзкейсы, DSL, архитектура, ADR, статус): `../documentation`. Клонировать из https://github.com/tinkoff-trade-strategies-checking/documentation. Источник правды по продукту; карта документов — `../documentation/README.md`.
- **frontend** (Angular + Taiga UI): `../frontend`. Клонировать из https://github.com/tinkoff-trade-strategies-checking/frontend.
- **backend** (Java, Spring Boot + Spring Modulith; источник OpenAPI и инфраструктуры `deploy/`): `../backend`. Клонировать из https://github.com/tinkoff-trade-strategies-checking/backend.
- **core** (C++20 ядро симуляции рынка; источник `.proto`): `../core`. Клонировать из https://github.com/tinkoff-trade-strategies-checking/core.

- **dsl** (язык стратегий; спецификация — `../documentation/dsl.md`): `../dsl`. Клонировать из https://github.com/tinkoff-trade-strategies-checking/dsl.
- **.github** (общие шаблоны issue и PR для всех репозиториев организации): `../.github`. Клонировать из https://github.com/tinkoff-trade-strategies-checking/.github. Шаблоны правятся только здесь, в репозиториях своих не заводим.

`frontend-ai`, `backend-ai`, `core-ai` — приватный архив ранней версии, сгенерированной ИИ. Неактуальны: не клонировать, не брать оттуда код и решения без явной просьбы.

## Как работать

- **Нет конкретной задачи** — начни со скилла `next`: он покажет, что мешает, чего не хватает проекту, и предложит следующую задачу с доски.
- Задачи — только по issue с [доски](https://github.com/orgs/tinkoff-trade-strategies-checking/projects/2). Процесс, ветки, коммиты, PR, когда обновлять документы — `workflow.md`.
- Перед фичей найди её ФТ, INV и UC в `../documentation` поиском по ID, не читай документы целиком.
- Изменение в нескольких репозиториях — по одному PR в каждом, в порядке контракта (ADR-0007): `core` (`.proto`) → `backend` (копия `.proto`, `api/openapi.yaml`) → `frontend` (копия OpenAPI).
- Коммить и пушь только в тот репозиторий, где изменение. В `home` — только то, что общее для всех репозиториев.
- Если документация противоречит существующему коду, следуй соглашениям, принятым в самом коде, а в финальном ответе укажи каждое найденное несоответствие между документацией и кодом и предложи исправления. Исключение — инварианты из `../documentation/invariants.md`: их нарушение в коде считается багом, его не повторяют, а сообщают о нём.
- Пишем по-русски, коротко. Команда скептически относится к сгенерированному тексту: каждое утверждение — по решению команды, не по догадке.

## Поддержание контекста

Ты запущен из `home`, и только этот файл гарантированно у тебя в контексте. Контекст проекта — этот файл, `workflow.md`, `AGENTS.md` соседних репозиториев и `../documentation` — поддерживаешь ты сам, никто другой его не обновит.

- **В конце каждой задачи**, до PR, сверься с таблицей «Когда обновлять документы» в `workflow.md` и обнови всё, что изменение сделало неверным, — в том же PR того репозитория, где изменение.
- **Указание оказалось неверным** (путь, команда, ветка, имя репозитория, правило) — исправь его сразу, в этой же задаче, а не только обойди.
- **Пришлось что-то выяснять, чего нет в контексте**, и это пригодится следующей сессии — допиши в подходящий файл: общее для всех репозиториев — сюда, про один репозиторий — в его `AGENTS.md`, про продукт — в `../documentation`.
- **Не записывай** то, что видно из кода или `git log`, и разовые подробности задачи — они раздувают контекст.
- Этот файл держи коротким: указатели и правила, без пересказа документов.
- Важное — в репозиторий, не в личную память агента: её не видят коллеги и другие агенты.
- Заметил, чего не хватает самому проекту (проверки, команды, правила, скилла), — заведи задачу или исправь сразу (скилл `next`, «Самосовершенствование»). Полная сверка контекста с реальностью — скилл `context-audit`: по просьбе, перед синком команды или если подозреваешь, что контекст устарел.

Изменения в `home` — через ветку и PR, как в остальных репозиториях.

## Что лежит в home

| Путь | Что |
|---|---|
| `workflow.md` | доска, Status / Size / Priority, задача от начала до конца, коммиты и PR, когда обновлять документы |
| `.agents/skills/` | общие скиллы (Codex, opencode); `.claude/skills/` — переходники для Claude Code |
| `scripts/clone-repos.sh` | клонирует недостающие репозитории рядом с `home` |
| `scripts/worktree.sh` | worktree на задачу: `start <repo> <тип> <N>`, `list`, `clean` |
| `review/` | проверка работы агентов: чек-лист ревью, кейсы оценки ревьюера, барьер (`README.md`) |
| `scripts/review-stats.sh` | метрики: откаты, отклонённые PR, непроверенные изменения |
| `scripts/project-health.py` | здоровье проекта: слой проверки репозиториев, CI, доска, PR, оценка ревьюера |
| `design/` | генераторы hi-fi макетов для Figma (свой `AGENTS.md`) |
| `context/` | исходники: ТЗ, презентация требований, схема стека |

Скиллы: `next` — что делать дальше и чего не хватает проекту; `verify` — прогнать изменение перед PR; `pr-review` — ревью PR тремя ловцами багов по чек-листу; `review-eval` — оценка ревьюера на реальных багах; `miro-board` — Miro-доска; `context-audit` — сверка контекста с реальностью.

Перед PR — всегда `verify`, перед слиянием — `pr-review` (`workflow.md`, «Проверка»).

## Доступ к соседним репозиториям

Агент запущен в `home`, а пишет в `../<repo>`:
- Claude Code — `.claude/settings.json` добавляет соседние папки в `additionalDirectories` (после доверия папке);
- Codex — запускать с `--add-dir ../documentation --add-dir ../frontend --add-dir ../backend --add-dir ../core --add-dir ../dsl --add-dir ../.github`;
- opencode — доступ к внешним папкам разрешён по умолчанию.

`AGENTS.md` соседнего репозитория не подгружается сам — открой его перед изменениями.
