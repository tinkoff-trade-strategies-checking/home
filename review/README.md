# Проверка работы агентов

Как агент доказывает, что изменение работает, и как мы проверяем сами проверки. По мотивам [How the Claude Code team thinks about verification](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/).

| Слой | Что | Где |
|---|---|---|
| Прогнать изменение | сборка, линтер, тесты, сквозной сценарий — до PR | скилл `verify`; команды — в `AGENTS.md` репозитория |
| Ревью | проверки с триггерами из diff, три независимых ловца багов, скептик, важность | скилл `pr-review`, правила — `checklist.md` (читаются из `main`) |
| Барьер | `gh pr create` без `verify` или `pr-review` в сессии: off / observe / enforce | `.claude/hooks/verify_gate.py` (только Claude Code) |
| Оценка ревьюера | находит ли ревьюер реальные баги и молчит ли на чистых PR | скилл `review-eval`, кейсы — `eval/cases.md`, результаты — `eval/results/` |
| Метрики | откаты, отклонённые PR, «Проверено: нет», находки «Важно» | `scripts/review-stats.sh` |

Правила процесса (три попытки, нестабильные тесты, режим наблюдения, промахи → правила) — `workflow.md`, раздел «Проверка».

## Барьер

Режим — в файле `.claude/verify-gate.mode` (`off`, `observe`, `enforce`; нет файла — `observe`). Файл локальный, в git не попадает.

- `observe` — ничего не блокирует, пишет в `.claude/verify-gate.log`, что было бы заблокировано. Сначала смотрим журнал на ложные срабатывания.
- `enforce` — блокирует `gh pr create`, если в сессии не было `verify` или `pr-review`. Пропускает, если в описании PR есть `Проверено: нет — <причина>`, и после двух блокировок в одной сессии, чтобы агент не застревал.
