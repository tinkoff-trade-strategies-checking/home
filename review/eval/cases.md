# Кейсы оценки ревьюера

Набор для скилла `review-eval`. Инцидент — PR, в котором был баг, найденный позже; ревьюер должен его найти. Контроль — влитый PR, к которому потом не было исправлений; ревьюер не должен находить в нём «Важное».

Состояние кода — коммит squash-слияния PR в истории репозитория: diff ревью — `<коммит>^..<коммит>`.

**Набор:** `test` — только для оценки, по нему правила не пишутся; `tune` — можно смотреть при правке `review/checklist.md`. Если правило в чек-листе написано по кейсу, кейс переносится в `tune`, а в `test` добавляется новый — иначе оценка меряет запоминание, а не поиск.

Ответ — одно предложение: находка засчитывается, только если описывает именно этот баг.

## Как пополнять

- Каждый баг, дошедший до `main` или найденный только человеком, — новый инцидент: PR, где он появился, и ответ одним предложением.
- Контроль — влитый PR, к которому за месяц не было исправлений и откатов; размер — как у инцидентов.
- Кейсы из закрытых архивов `*-ai` сюда не пишем: `home` публичный.
